# 动效与性能验证

2026-10-19，基于 v0.7.0 的本地优化；未合并、未发布新版本。

## 动效与行为

- 短反馈使用 120 ms，选中与浮层进入使用 240 ms，NG 强调继续使用 400 ms。没有新增循环装饰动画或必填属性。
- 下拉、菜单、提示、日期时间、对话框和抽屉按方向进入、退出。退出阶段不接受指针操作，Radix 继续负责焦点、Escape 与挂载生命周期。
- 分段、Tabs 与导航指示器共用可中断的位移动效，从当前视觉位置继续切换。布局尺寸变化每帧合并测量，导航宽度切换不再逐帧挤压整页布局。
- 滑块位置立即跟随输入，数值提示只淡入淡出。数字流连续更新时取消旧动画、保留最新数字的可读性，低频变化仍只动画变化位。
- SnackbarProvider 保留不可交互、对辅助技术隐藏的短暂退出视图，清除回调仍立即生效。直接使用 Snackbar 并由父组件立即卸载时无法保留退出视图；需要完整退出效果时使用 Provider。
- 系统开启减少动态效果时，状态直接切换；键盘焦点、语义色及数字仍完整呈现。

## 性能改动

- 时间选项按合法步长生成，并索引时／分候选；普通一分钟步长从遍历 86,400 秒改为生成 1,440 个候选。日历校验复用约束输入，时间列只在打开或选中值变化时调整局部滚动。
- 稳定受控状态更新函数、主题和 Snackbar 上下文；监听器不因普通重绘反复安装。最新回调、受控值和表单重置保持原有语义。
- 表格复用排序比较器与选择集合，将更新限制到变化行。相机缩略图和数字字符减少无关重绘，数字格式器及小数分隔符采用有界缓存。
- 示例高级区域与工业区域分块加载；压力场景为独立入口，默认不运行。共享样式和包导出保持兼容。

使用方应以不可变数据更新行／帧对象；未变化的行、列定义、事件回调尽量保持引用稳定。缓存不会替代服务端分页或虚拟滚动；本轮不提供万行同时渲染能力。

## 正式对比

环境：Windows，Intel Core i5-1135G7（8 逻辑处理器），Chrome 155.0.8059.81，1440 × 1000，无 CPU 节流。帧间隔中位数约 16.6 ms，与 60 Hz 调度一致，但并非硬件刷新率检测。

两个版本使用同一压力场景和测量脚本，生产构建各预热一次，再顺序采样五轮；不与浏览器回归同时执行。场景包含 10,000 行分页数据（每页 100 行）、8 路固定本地 SVG 缩略图每秒更新状态 5 次、24 项读数每秒更新 20 次。每轮执行 50 次滑块键盘操作、首次打开秒精度时间面板、选择表格一行，并停止更新。

下表为**五轮指标的中位数**，完整逐轮数值见 [performance-results.json](performance-results.json)。

| 指标 | 优化前 | 优化后 | 判断 |
| --- | ---: | ---: | --- |
| 交互延迟中位数 | 9.4 ms | 11.2 ms | 略有上升，不宣称所有交互加速 |
| 交互延迟 P95 | 19.7 ms | 17.2 ms | 低于 50 ms 目标 |
| 帧间隔中位数 | 16.6 ms | 16.6 ms | 基本不变 |
| 帧间隔 P95 | 16.9 ms | 16.9 ms | 低于 25 ms 目标 |
| 选择一行触发单元格渲染 | 200 次 | 2 次 | 减少 99% |
| 单轮全部单元格渲染 | 800 次 | 202 次 | 开始／停止场景也不再带动无关表格行 |
| 五轮总长任务（>50 ms） | 0 | 0 | 时间首次打开窗口也未记录长任务 |
| 时间面板打开自动化耗时 | 73.8 ms | 78.0 ms | 包含自动化调度及 UI 状态等待，不是纯计算耗时 |
| 展示页初始静态 JS 依赖 | 531.27 kB | 388.67 kB | 减少约 26.8%，不含随后动态模块 |

交互延迟采用 keydown → requestAnimationFrame → setTimeout 的下一次绘制机会代理值，**不是浏览器 INP 指标，也不保证精确的屏幕呈现时刻**。帧数据来自 requestAnimationFrame，长任务来自 PerformanceObserver；表格计数来自单元格 render 调用，相机与读数 tick 计数表示更新次数，不等同于 React 内部提交次数。

该采样未发现超过目标的尾部延迟，但不构成任意设备固定帧率保证。时间面板打开耗时略升，新增进入动画与调度均在观察窗口内，不能仅凭该计时归因。高级和工业模块在首次渲染后仍会并行加载；静态体积减少不等同于完整页面总下载量同比减少。早期探索中出现过 52–74 ms 长任务，正式隔离运行未复现，不能将其消失全部归功于优化。

## 复现与检查

1. 修改组件前，用当前 `showcase/performance.*` 场景构建基线并保存为 `dist-baseline/`；两个版本必须使用相同场景。
2. 运行 `npm run build:demo` 构建优化版本。
3. 分别启动 `npx vite preview --outDir dist-baseline --port 4173` 和 `npx vite preview --outDir dist-demo --port 4174`。
4. 顺序运行 `node scripts/benchmark.mjs http://127.0.0.1:4173 before` 和 `node scripts/benchmark.mjs http://127.0.0.1:4174 after`。每次自动预热一轮、记录五轮；原始逐帧数据写入 `performance-results/`，不受 Playwright 清理影响。
5. `/showcase/performance.html` 可手动开始／停止压力场景，停止和卸载均清理定时器。

验证：49 项单元测试、11 项浏览器测试通过，包含跨午夜与小数步长、稳定回调、局部行更新、快速切换、动画取消、退出焦点恢复、减少动效和停止更新。另检查类型、库及展示页构建、token 一致性。
